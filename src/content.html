topic 1

1 · Introduction to compiler

A computer understands only machine code (0s and 1s). People write programs in high-level languages (C, Java, Python). This is source code. A language processor translates source code so the computer can run it.

CompilerReads the whole program in one go and translates it into a target program.C, C++ · output: target program, run later
InterpreterRuns the source program directly, statement by statement. No target program.Python (scripting language)
AssemblerTranslates assembly language into machine code.mnemonics: ADD, SUB, MUL, DIV, MOV
Hybrid (Java)Compile to bytecode, then a virtual machine interprets it.JIT compilers turn bytecode into machine code just before it runs
A compiler is a program that reads the whole program written in a source language/high level language as a whole in one go and translates it into an equivalent program in a target language.
Instead of producing a target program as a translation, an interpreter appears to directly execute the operations specified in the source program on inputs supplied by the user.
CompilerInterpreter
Readswhole program at onceone statement at a time
Outputtarget program (machine/assembly code)no target program, gives output directly
Errorsreports after it scans the programstops at the first error
Speed of runningfaster (already translated)slower (translates while running)

The jobs of a compiler: translation, validation (find errors), optimization.

2 · Different phases of compilation

A compiler works in 6 phases. Each phase takes the output of the one before it.

"Lazy Students Sleep In Our Class": Lexical, Syntax, Semantic, Intermediate, Optimization, Code generation.
LexicalMakes tokens. Removes spaces and comments.
SyntaxChecks structure with a grammar. Builds a parse tree.
SemanticChecks meaning: types, declared variables.
IntermediateMachine-independent code (three-address code).
OptimizationBetter code, same result.

3 · Lexical analysis and regular expressions

The lexical analyzer (also called scanner or tokenizer) reads the source code as a stream of characters, from left to right. It cuts the stream into tokens and sends them to the parser. It also removes white space and comments. It puts identifiers in the symbol table.

TermMeaningExample
Tokena class (category) of stringsidentifier, number, keyword, operator, separator
Lexemethe actual characters in the code that match a tokenresult, a, 10
Patternthe rule that describes the lexemes of a token (a regular expression)[a-z][a-zA-Z0-9]*
A lexical token is a sequence of characters that can be treated as a unit in the grammar of the programming languages. Token format: <token-name, attribute-value>

Example from class: int a, b; a = 10; return 0; inside int main() { ... } gives 18 tokens: int main ( ) { int a , b ; a = 10 ; return 0 ; }. Comments are not tokens.

Try: how many tokens in printf("%d", result);?

7 tokens: printf · ( · "%d" · , · result · ) · ;. Rule: a whole string literal in quotes is one token. (The slides' example printf("..."); has 5: printf ( "..." ) ;)

Regular expressions (RE)

An RE is a short formula that describes a set of strings (a language). The lexer uses REs as patterns.

OperatorMeaningExample → strings
a|ba or b (union)a, b
aba then b (concatenation)ab
a*zero or more a (Kleene star)ε, a, aa, aaa, …
a+one or more aa, aa, …
a?zero or one a (optional)ε, a
[a-z]any one letter a to za, q, z

Class example: num → digit+ ( . digit+ )? means "one or more digits, then optionally a dot and more digits": 7, 42, 3.14.

Class example: (a|b)*ab = any mix of a and b, but it must end with ab: ab, aab, bab, aaab. Its transition diagram (from your notes):

Regular expressions (finite automata) cannot check balanced brackets like ((())). They cannot count deep nesting. That is why the parser uses a context-free grammar, which is more powerful.

topic 5

5 · Parse trees: leftmost (LMD) and rightmost (RMD) derivation

Derivation: A sequence of grammar rule applications and substitutions that transform a starting non-term into a sequence of terminals / tokens.

At each step you replace one non-terminal by one of its right sides. Which one?

LMD (leftmost)RMD (rightmost)
Always replace the leftmost non-terminal.Always replace the rightmost non-terminal.
Used by top-down parsers (LL).Its reverse is used by bottom-up parsers (LR).

A parse tree shows a derivation as a tree. The root is the start symbol. Inner nodes are non-terminals. Leaves are terminals. Read the leaves left to right and you get the string.

Assignment 01, Q1(b): LMD and RMD of (a, (a, a))

In an LMD, check every line: did you replace the leftmost non-terminal? A common mistake is to replace a non-terminal in the middle. Also: an unambiguous grammar gives the same tree for LMD and RMD. Only the order of steps changes.
topic 4 · mid Q1 (7 marks)

6 · Ambiguous and unambiguous grammar, and conversion

A grammar is ambiguous if there exists a string that has more than one leftmost derivation (more than one parse tree, or more than one rightmost derivation).

Why is that bad? Two trees = two meanings. From your notes: id + id * id with 3, 2, 5. Watch both trees.

The Ambiguous Grammar does not consider the Precedence and Associativity.

Precedence and associativity

PrecedenceWhich operator goes first. * / are higher than + −. ^ is highest.3 + 2 * 5 = 13, not 25
Left associativeSame operator twice: do the left one first. + − * /3 + 2 + 1 → 5 + 1 → 6
Right associativeDo the right one first. ^ (power)3 ^ 5 ^ 2 = 3 ^ 25
Lower precedence operation rules should be declared in the upper level in the Grammar. Higher precedence operation rules should be declared in the lower level in the Grammar. Operators with same precedence must be resolved by Associativity.
Low on top, high at the bottom. Left associative → left recursive (E → E + T). Right associative → right recursive (F → G ^ F).

The exam answer format (Quiz 01, faculty solution)

How to show a grammar is NOT ambiguous

Some questions ask "ambiguous or NOT". A layered grammar is not ambiguous when:

  • each operator appears in one rule only, at one level;
  • each rule recurses on one side only (E → E @ S | S, not E → E @ E);
  • so for any string there is only one way to build the tree.

Mid Autumn-23 Q1: E → E@S | S, S → S#B | B, B → C~B | C, C → C?A | ε, A → a. Every operator (@, #, ~, ?) has its own level and recurses on one side ∴ NOT ambiguous. Write it like this: "Each operator is at a different level of the grammar and each rule is either left or right recursive, never both. So every string has exactly one leftmost derivation. ∴ The grammar is unambiguous."

Note: the printed paper shows C → C?A / E. With E there, no terminal string can be made at all, so it must be ε (we checked by computer). If you see something like this, state what you assume.

The pattern X → X op X (same non-terminal on both sides of an operator) is the sign of ambiguity. Look for it first. Assignment Q2(iv) B → B∆B | b is ambiguous for this reason, even though E and T look fine.
Assignment 01 Q2 and Q3: quick answers

(i) S → AS | b, A → SA | a: ambiguous. abab has two LMDs:
S ⇒ AS ⇒ aS ⇒ aAS ⇒ aSAS ⇒ abAS ⇒ abaS ⇒ abab
S ⇒ AS ⇒ SAS ⇒ ASAS ⇒ aSAS ⇒ abAS ⇒ abaS ⇒ abab
This is not an operator grammar, so the precedence recipe does not apply. Showing ambiguity is the part that scores.

(ii) S → aa | aS | a: ambiguous. aa has two LMDs: S ⇒ aa, and S ⇒ aS ⇒ aa. Fix: S → aS | a.

(iii) S → aS | aSbS | ε: ambiguous (the dangling-else shape). aab has two LMDs: S ⇒ aS ⇒ aaSbS ⇒ aabS ⇒ aab and S ⇒ aSbS ⇒ aaSbS ⇒ aabS ⇒ aab.

(iv) B → B∆B | b is ambiguous (b∆b∆b). Fix that level: B → B∆C | C, C → b (assume ∆ left associative).

Q3 E → E+E | E<E | E=E | id: ambiguous (id+id<id has two trees). Assume precedence + > < > =, all left associative:
E → E = R | R, R → R < P | P, P → P + Q | Q, Q → id.

7 · Left recursion: LRG → RRG

A grammar is left-recursive if it has a non-terminal A, such that there is a derivation A ⇒⁺ Aα, for some string α.

In simple words: a rule like A → A α, where the left side appears again as the first symbol on the right. A top-down parser then loops forever:

A → A α₁ | A α₂ | β₁ | β₂ (α = what follows A, β = the others) ⇓ A → β₁ A' | β₂ A' A' → α₁ A' | α₂ A' | ε
"β goes first, α goes to the new guy, new guy ends with ε."

Indirect left recursion (harder, 4 marks in Quiz 01)

Sometimes the loop goes through another non-terminal: A → B c and B → A e. Method (from the faculty solution):

  1. Order the non-terminals: A, B, C (top to bottom).
  2. Fix A's direct left recursion.
  3. In B, replace any A … at the start with A's new rules. Then fix B's direct left recursion.
  4. In C, replace A … and B … at the start. Then fix C. Box each result.
Assignment 01 Q5 (i) and (ii)
Do not forget ε in the A' rule. Do not forget to add A' at the end of every β alternative. Keep the order of symbols inside α exactly as it was.
topic 7 · quiz Q1 (5 marks)

8 · Deterministic vs non-deterministic grammar: left factoring (NDG → DG)

A grammar is non-deterministic (NDG) when two alternatives of the same non-terminal start with the same symbols. Example: A → a b | a c. Looking at a, the parser cannot know which one to pick. A deterministic grammar (DG) never has this problem.

A → α β₁ | α β₂ | γ (α = common prefix) ⇓ A → α A' | γ A' → β₁ | β₂ (if a βᵢ is empty, write ε)
"Pull out the common part once. The new guy gets the leftovers." Repeat until no two alternatives start the same way.
Assignment 01 Q4 (i) and (ii)
Take the longest common prefix, not just the first letter. If one alternative is exactly the prefix (like ab in abcA | ab), the new rule gets ε. Also check the new non-terminals: they can be non-deterministic again (S' → cA | cB needs S'').
Left recursion removalLeft factoring
ProblemA → A α (loops forever)A → α β₁ | α β₂ (cannot choose)
ResultLRG → RRGNDG → DG
New rule ends withA' → α A' | εA' → β₁ | β₂

9 · Classification of parsers

Top-down parserBottom-up parser
Starts from the top (start symbol) and goes down to the leaves.Starts from the leaves (input) and goes up to the start symbol.
Uses Left Most Derivation.Uses Reverse of Right Most Derivation.

Cannot use left recursion. Predictive needs a deterministic grammar.Can handle left recursion.
1. Top-Down Parser: The parse tree is created top to bottom, starting from the root. 2. Bottom-Up Parser: The parse tree is created bottom to top, starting from the leaves. Both Top-Down and Bottom-Up parsers scan the input from left to right (One symbol at a time).
Brute force parser = top-down with backtracking. It is not bottom-up. (Mid Aut-23 Q3(e) asked exactly this.)
topics 9–10

10 · Introduction to top-down parsing

Two kinds of top-down parser:

Recursive descent (backtracking)One procedure per non-terminal. Tries the alternatives one by one. Goes back on failure.general, but not efficient
Predictive (no backtracking)Looks at the next token and picks the right rule the first time.efficient · needs an LL(1) grammar
When re-writing a non-terminal in a derivation step, a predictive parser can uniquely choose a production rule by just looking the current symbol in the input string.

11 · The LL(1) parser: the idea

L= Left-to-right scanning of input
L= Leftmost derivation (top-down)
(1)= 1 look-ahead token to decide
First L: Left to Right Scanning. Second L: Leftmost derivation. 1: one input symbol of look-ahead at each step to make parsing action decisions.

From your notes, LL(1) works only on a grammar that is:

1. Unambiguous (lesson 6) · 2. No left recursion (lesson 7) · 3. Deterministic, left-factored (lesson 8)

The full method has 4 parts. Do them in this order in the exam:

1 FIRST→2 FOLLOW→3 table→4 parse the string→tree + conclusion
If the grammar in the question is left recursive (for example E → E + T), remove left recursion first (lesson 7), then do LL(1). The class grammar E → TE' … is exactly the slides grammar after this step, with F renamed to M.
topic 12

12 · FIRST and FOLLOW sets

FIRST

The FIRST set of a grammar symbol X, written as FIRST(X), contains the terminals that can appear at the beginning of strings derived from X.
1. If X is a terminal, then FIRST(X) = {X}. 2. If X → ε, include ε in FIRST(X). 3. If X → Y1Y2…Yn, add FIRST(Y1) excluding ε. If Y1 can derive ε, continue to Y2 and so on. 4. If every symbol on the right-hand side can derive ε, include ε.
Baby version (your notes): look at the first symbol of each alternative.
• terminal → put it in FIRST. Done.
• ε → put ε in FIRST.
• non-terminal → find its FIRST and copy it (without ε). If it had ε, also look at the next symbol.

FOLLOW

The FOLLOW set of a non-terminal A, written as FOLLOW(A), contains the terminals that can appear immediately after A in a sentential form.
1. Put the end marker $ in FOLLOW(S), where S is the start symbol. 2. If A → αBβ, add FIRST(β) excluding ε to FOLLOW(B). 3. If A → αB or A → αBβ where β ⇒* ε, add FOLLOW(A) to FOLLOW(B).
Baby version (your notes): start symbol gets $. Then find B on every right side and look at what is just after it.
• terminal → add it.
• non-terminal → add its FIRST without ε. If it has ε, keep looking right.
• nothing → add FOLLOW of the parent (the left side).
FOLLOW never has ε. FIRST never has $. FOLLOW is only for non-terminals. Most lost marks: forgetting $ in the start symbol, and forgetting "nothing after → add FOLLOW(parent)".
topic 13

13 · Building the LL(1) parsing table

Rule for each production A → α:
1. For every terminal a in FIRST(α), put A → α in M[A, a].
2. If ε is in FIRST(α), put A → α in M[A, b] for every b in FOLLOW(A) (this includes $).
3. Empty cells = error.
Your notes: "Find out from FIRST: which rule gives which terminal. If ε is in FIRST, go to FOLLOW."
topic 13 · mid Q2 (8 marks)

14 · Parsing a string with the stack

The loop (repeat until $ meets $):
• Start: stack = $ S, buffer = input $, LA at the first token.
• Top is a non-terminal A: look at M[A, LA]. Pop A. Push the right side reversed. (ε: push nothing.)
• Top is a terminal: it must equal LA. Pop it and move LA right (match).
• Top = $ and LA = $: accept. Empty cell or mismatch: error.

15 · FIRST–FOLLOW conflicts (when a grammar is NOT LL(1))

A FIRST/FIRST conflict occurs when two or more alternative productions of the same non-terminal have overlapping FIRST sets.
A FIRST/FOLLOW conflict occurs when a production can derive the empty string ε and a terminal that can begin another alternative also belongs to the FOLLOW set of the non-terminal.
